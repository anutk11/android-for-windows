# תכנון G1-TLS: משתני thread-local של ELF על Windows

מצב: **בודק 3 הגיב (Issue #4), והתיקונים שלו נכנסו לגרסה הזאת.** הקוד נכתב בענף `g1-tls`.
סימון: **[נמדד]** = מבוסס על פלט CI, **[השערה]** = עוד לא נבדק.

## 1. מה הקוד באמת עושה עם `fs:` [נמדד]

היסטוגרמת `fs:[disp32]` מתוך `--patch-report` (ריצה 45021907735):

| ספרייה | `mov reg, fs:[0x28]` (stack guard) | `mov reg, fs:[0x0]` (tp) | `add reg, fs:[0x0]` | כתיבה דרך `fs:` |
|---|---|---|---|---|
| libc.so | 843 | 127 | 2 | 0 |
| linker64 | 1619 | 58 | 0 | 0 |
| libc++_shared.so | 1887 | 0 | 0 | 0 |

בנוסף יש ב-libc שבעה אתרי `fs:[reg]` בתוך פונקציות, כולם ב-`gwp_asan` (`initPRNG`).

**מסקנה:** כל גישה ישירה היא **קריאה** של שני תאים שערכם קבוע לכל thread: tp (תא 0) וה-guard (תא 5). לכן המודל הנוכחי, שבו לכל thread יש עותק של התאים ב-TEB TlsSlots, נכון לכל הקוד שנמדד.

**הקשחת השער (חלק מ-G1-TLS):**
- `fs:[disp32]` מותר רק כקריאה של `0x0` או של `0x28`.
- כל דבר אחר נחשב "fs לא נתמך" וחוסם את הטעינה: כתיבה, offset אחר, או `fs:[reg]` בתוך פונקציה.
- התוצאה הצפויה היא ש-libc תיחסם בגלל שבעת אתרי `gwp_asan`. לכן החלק השני של G1-TLS הוא טיפול באתרים האלה (סעיף 6).

## 2. פריסת הזיכרון לכל thread (Variant II, כמו ב-x86_64 Linux)

```
 נמוך                                                   גבוה
 [ static TLS של מודול N ] ... [ static TLS של מודול 1 ] [ תאי bionic: 16 x 8 ]
                                                          ^ tp  (fs:[0] == tp)
```

- **tp** הוא כתובת תא 0, ותא 0 מכיל את tp עצמו. זה מה שהקוד מניח כשהוא מבצע `mov rax, fs:[0]` ואז `mov eax, [rax+tpoff]`.
- **לכל מודול עם `PT_TLS`** מוקצה offset שלילי: `tpoff_m = -off_m`.
  - חישוב (תוקן לפי בודק 3): `A = max(p_align_m, 1)`, `r = p_vaddr_m mod A`, `off_m = roundup(off_{m-1} + p_memsz_m + r, A) - r`.
  - כך מובטח גם שאין חפיפה (`off_m >= off_{m-1} + p_memsz_m`) וגם ש-`(tp + tpoff_m) ≡ p_vaddr_m (mod A)`.
  - `p_align` חייב להיות חזקה של 2. אם הוא גדול מ-64KB, הספרייה נדחית עם הודעה.
- **מיקום tp (תוקן לפי בודק 3):** `max_align = max(16, max p_align)`, `tp_off = roundup(off_N, max_align)`, `tp = base + tp_off`.
  - הנוסחה הקודמת (`tp = base + off_N`) הייתה שוברת את היישור של מודול שדורש יישור גדול, כש-`off_N` לא מתחלק ב-`max_align`.
- **הקצאה אחת לכל thread:** בגודל `roundup(tp_off + 128, 4096)`, כך שתמיד יש לפחות 128 בתים חוקיים אחרי tp.
- **אתחול לכל thread:** מעתיקים `p_filesz` בתים מ-`.tdata`, ומאפסים את השאר עד `p_memsz` (`.tbss`).
- **מתי:** הפריסה נקבעת פעם אחת, אחרי טעינת כל הספריות שנטענות בהתחלה ולפני שרץ קוד כלשהו שלהן.
  - ספרייה עם `PT_TLS` שנטענת מאוחר יותר (dlopen) נדחית ב-G1 עם הודעה ברורה. TLS דינמי (DTV) שייך ל-G2.

## 3. רלוקציות

| רלוקציה | ערך |
|---|---|
| `R_X86_64_TPOFF64` | `S + A + tpoff_m(S)`. שלילי. `m` הוא המודול שמגדיר את הסמל. אם `sym_idx == 0` (משתנה `static __thread`), אז `S = 0` ו-`m` הוא המודול שנטען כרגע. (בודק 3) |
| `R_X86_64_DTPMOD64` | מזהה המודול (1..N) |
| `R_X86_64_DTPOFF64` | `S + A` (offset בתוך בלוק המודול) |
| `R_X86_64_TLSDESC` | **נדחה** עם הודעה. [השערה] ב-x86_64 NDK לא נפלט כברירת מחדל. זה ייבדק בספריית הבדיקה. |

**`__tls_get_addr(ti)`** (`sysv_abi`) מחזיר `tp + tpoff[ti->module] + ti->offset`.
- הנוסחה מכסה גם Local-Dynamic, שבו `offset == 0`.
- מזהה מודול מחוץ לטווח `1..N` עוצר את התהליך עם הודעה.
- הדריסה מתועדת בקוד כזמנית ל-G1.

הטוען מספק את `__tls_get_addr` בעצמו, וזה גובר על הייצוא של libc. הסיבה: המימוש של bionic קורא את ה-DTV ואת `libc_shared_globals->static_tls_layout`, שלא ממולאים לפני האורקל של בודק 2. **[פתוח ל-G2]** כש-`libc_shared_globals` יאומת, נבנה DTV אמיתי ונחזיר את המימוש של libc.

## 4. threads

- `afw_tls_thread_init()` מקצה את הבלוק המשולב, מאתחל אותו, וכותב ל-TEB את tp (לתא 0) ואת ה-guard (לתא 5).
- השחרור קורה ביציאת ה-thread, דרך FLS callback.
- **כללים (בודק 3):**
  - **אין `FlsFree` בכלל.** הוא מריץ את ה-callback על ערכים של threads חיים.
  - ה-callback לא נקרא ב-`TerminateThread`. המחיר הוא דליפה של בלוק אחד, וזה מקובל.
  - **לא לוקחים את ה-Loader Lock של Windows בזמן שמחזיקים את המנעול של שכבת ה-VMA** (למשל `LoadLibrary`).
- **[פתוח ל-G2]** `pthread_create` של libc האמיתית מקצה TLS לפי `static_tls_layout`. ב-G1 רק הטוען יוצר threads. השאלה אם `clone` שלנו יבנה TEB, או ש-`pthread_create` יוחלף, נשארת להחלטה ב-G2 על בסיס ניסוי, כמו שסוכם.

## 5. בדיקות (`test/tls_test.c`, נבנה ב-NDK)

1. משתנה ב-`.tdata` עם ערך התחלתי שונה מאפס. כל thread רואה את הערך ההתחלתי.
2. משתנה ב-`.tbss`. כל thread מקבל אפס.
3. משתנה `aligned(64)`. מוודאים ש-`&v % 64 == 0` בכל thread.
4. גישה בשני מודלים:
   - `initial-exec` דרך `TPOFF64` ו-`mov rax, fs:[0]`.
   - `general-dynamic` דרך `__tls_get_addr`.
   - שני המודלים חייבים להחזיר אותה כתובת.
5. שני threads ומחסום (barrier): כל אחד כותב ערך משלו, ממתין, ובודק שהערך שלו לא השתנה.
6. בדיקה שלילית: ספרייה שנטענת מאוחר עם `PT_TLS` נדחית.
7. השער: ספרייה עם `fs:[0x10]` (offset שלא מותר) נחסמת.
8. **בדיקת יחידה של חישוב הפריסה (בודק 3)**, בצד המארח ב-C. היא מכסה מקרים שה-NDK לא מייצר: `p_vaddr = 0x10` עם `p_align = 64`, `p_align = 0`, ושני מודולים (64 ואחריו 8/8). בכל מקרה היא בודקת יישור, היעדר חפיפה, ו-128 בתים אחרי tp.

ה-CI בודק גם את הדיסאסמבלי של ספריית הבדיקה, ומדפיס איך clang ניגש ל-TLS בכל מודל. ככה ההנחות בסעיפים 1 ו-3 נמדדות ולא מנוחשות.

## 6. `fs:[reg]` ב-libc (gwp_asan) [נמדד]

הפקודות עצמן (מהלוג של `bionic-probe`):

| RVA | פקודה | גישה |
|---|---|---|
| `0x4516e`, `0x4524a`, `0x51f7d` | `mov eax, fs:[rax+0x4]` (4 בתים) | קריאה |
| `0x51d28`, `0x51df7` | `mov eax, fs:[rcx]` (3) | קריאה |
| `0x51d40`, `0x51e0f` | `mov fs:[rcx], eax` (3) | **כתיבה** |
| `0x51d56` | `and eax, fs:[rcx+0x4]` (4) | קריאה + דגלים |
| `0x51d62` | `mov fs:[rcx+0x4], eax` (4) | **כתיבה** |
| `0x51fe0` | (בלוג) | |

בודק 3 צדק: חלק מהגישות הן כתיבות, ואין רגיסטר יעד פנוי. **ההחלטה:** טרמפולינה כללית ב-`jmp`, לפי ההצעה שלו.

```
  site:  jmp stub ; nop...        ; 5 בתים: הפקודה + פקודות סמוכות שאפשר להזיז
  stub:  lea  rsp, [rsp-128]      ; מעל ה-red zone, לא משנה דגלים
         push r11
         mov  r11, gs:[TEB slot 0] ; tp
         <הפקודה המקורית, בלי fs:, עם r11 כאינדקס נוסף: [r11 + rcx + disp]>
         pop  r11
         lea  rsp, [rsp+128]
         <הפקודות הסמוכות שהוזזו>
         jmp  next
```

- **התנאי לפקודה עצמה:** הכתובת היא base בלבד או base+disp, בלי index. אחרת אין מקום ל-r11 כאינדקס, והאתר נדחה.
- **התנאים לפקודות שמוזזות:** בדיוק כמו ב-Form B. הן חייבות להיות בלתי תלויות במיקום (או לעבור חישוב מחדש של `disp32` ביחס ל-rip), ושום ענף לא יכול לנחות בתוכן.
- **אתר שלא עומד בתנאים** נדחה והופך ל-`ud2`, והשער חוסם את הספרייה.
- **בדיקה:** ספריית NDK עם `static __thread` במודל initial-exec. ה-CI מוודא שנפלט בה `fs:[reg]`, כולל קריאה, כתיבה ו-`and`.
